CONTROLLED WORKFLOW

From vulnerability to approved repair

Generation and verification remain separated. The harness decides test results; a human decides whether the patch is approved.

01

Detect

Identify unsafe code using static analysis and controlled local testing.

02

Patch

Create a minimal candidate without modifying the retained vulnerable sample.

03

Verify

Check compilation, normal behaviour, crash regression and unsafe-code removal.

04

Approve

Require manual review before promoting the candidate as the approved version.

05

Remember

Preserve verified regression evidence for future patch candidates.

MINIMAL SECURITY PATCH

Before and after

Vulnerable sample

UNSAFE 
char name[32];
strcpy(name, input);

An oversized value may exceed the destination buffer. This sample is retained only for controlled demonstration.

Approved version

VERIFIED 
if (strlen(input) >= sizeof(name)) {
    fprintf(stderr, "Error: input is too long\n");
    return 1;
}
memcpy(name, input, strlen(input) + 1);

Oversized input is rejected before copying while normal behaviour remains available.

SAFETY BOUNDARY

Supervised autonomy by design

KAVACH-Loop is an authorized defensive college prototype using locally created test files. It does not automatically merge or deploy patches and is not proposed for unsupervised operation on live or classified systems.
